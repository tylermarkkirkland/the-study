# Classic-OS: Creative Operating System

Personal portfolio prototype — a modern desktop OS rendered inside a monitor, inside a 3D-modeled room. See the global CLAUDE.md at ~/CLAUDE.md for this user's broader design/accessibility conventions; the overrides below apply specifically to this project.

- **Stack override**: Next.js (App Router) + TypeScript, not Vite + JS. This is a long-lived project meant to grow with more apps over time, so static types on the window manager and app registry are worth the extra ceremony.
- **Window system**: `src/lib/windowManager/windowReducer.ts` is the single source of truth (useReducer + Context via `src/components/WindowManager/WindowManagerContext.tsx`). Adding a new app = write a content component under `src/components/apps/`, register it in `src/components/WindowManager/appRegistry.tsx`, add an entry to `src/data/desktopIcons.ts`. No changes needed to the reducer, `WindowFrame`, or layout.
- **Room**: the root route `/` renders `RoomExperience`, which serves the real-time three.js/GLB room (`RoomScene3D`, using the hand-built `office.glb` + HDRI lighting) when WebGL is available and motion isn't reduced. Otherwise (no WebGL, reduced motion, or a runtime 3D error) it falls back to `FallbackDesktop` — the shared `OSDesktop` rendered fullscreen, so every app still works without the 3D room. Phones (`≤767px`, via `MobileGate`) get a "best on a bigger screen" notice instead, since the corner-pin homography is calibrated for desktop viewports. The 3D room corner-pins the shared `OSDesktop` onto the monitor's screen via a CSS `matrix3d` homography. (The earlier CSS-3D graybox room — `RoomScene`/`DeskProps`/`Monitor` — and the sticker-board feature were removed.)
- **Visual style**: modern macOS-like glass — translucent frosted chrome, rounded corners, soft depth shadows, traffic-light window controls, a bottom Dock, dark theme by default. Design tokens live as CSS custom properties in `src/app/globals.css` (dark on `:root`, light override under `[data-theme="light"]`, surfaced to Tailwind via `@theme inline`). Surfaces read through `--surface-bg`/`--surface-blur` indirection so the corner-pin monitor subtree can swap true `backdrop-filter` glass for an opaque fallback (backdrop-filter doesn't composite under a `matrix3d` ancestor).
- **Accessibility still applies** even though this is a personal/creative project, not a FamilySearch product: 44x44px touch targets, keyboard operability, visible focus states, and `prefers-reduced-motion` support (handled globally via `MotionConfig reducedMotion="user"` in `src/components/MotionProvider.tsx`) are all load-bearing, not optional polish.
